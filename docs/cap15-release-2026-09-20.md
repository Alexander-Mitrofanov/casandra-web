## Deployment and rollback

This is a paired runtime/backend/model release. Do not use a legacy dev0
wheelhouse to install this backend. The live scientific package versions match
the frozen validation environment. The existing systemd resource limits and
job storage are retained.

`deploy/activate-cap15.py` stages an offline, hashed package on the existing VM,
preflights it as the service account, drains jobs, and switches the release.
The first attempt rolled back because verification ran before the cleanup timer
restarted; a retry also exposed systemd's restart-rate limit. Both are handled in
the final script, and final deployment verification passed.

The final activation script is `/srv/casandra/staging/cap15-20260920/activate-cap15-v3.py`.
Its SHA256 is `3e65ae53c29464f6cec2424cff35d97c84f8ea835492d58f8ad077cfdc206775`.
The original hashed payload remains in the adjacent `paired-package/` directory.
The previous release and environment backups are retained there. To restore the
paired backend, runtime and model after draining jobs:

```bash
sudo python3 /srv/casandra/staging/cap15-20260920/activate-cap15-v3.py \
  /srv/casandra/staging/cap15-20260920/paired-package --rollback
```

Restore the previous frontend publication as well for a complete release rollback.

## Reproduction

The separate project folder `for_will_low_false_positives/` contains a brief
README, step-by-step process, exact dependencies, archived inputs, runnable
reconstruction commands and actual verification receipts. The exact release,
original classifier, specificity rules and public comparisons were reproduced.
Canonical alignments reproduce all HMM parameters; optional raw multithreaded
MAFFT realignment has two documented nondeterministic cases.

The observed public comparison is 146 to 58 calls among 2,640 annotation-reference
proteins. These are not certified biological false positives; exposure and limited
denominators constrain recall claims. See the handoff's council and manuscript evidence.
